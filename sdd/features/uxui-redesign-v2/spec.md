# Spec: UX/UI Redesign v2 (uxui-redesign-v2)

Source of truth: master prompt v2.1 (session 2026-08-05). This spec mirrors its scope; the prompt wins on conflict.

## Goal
Ship the UX/UI redesign that two previous runs failed to deliver: clean sidebar, correct collapse, simplified dashboard, robust uploads, optional project creation, document-data modal with composition/brand scoping, i18n parity, and mandatory visual validation with before/after evidence per unit.

## Units (acceptance criteria)

- **U1 — Clean sidebar** (`src/components/layout/AppShell.tsx`): nav = Dashboard + Mis proyectos only; remove "STACK ACTIVO" and "CONTRATO" cards; remove "PREMIUM APP" badge (logo + "Anclora Talent" only). Proof: grep absence of removed keys.
- **U2 — Correct collapse**: rail 72–88px, centered icons + tooltips; expanded 320px; `grid-template-columns` transition; collapsed state does NOT render the label span (`talent-shell-sidebar-link__label`); aside `min-w-0` + `overflow-hidden`; no main-panel overlap. Proof: screenshots 1366×768 + 1920×1080 expanded/collapsed, no horizontal overflow.
- **U3 — Dashboard** (`src/app/(app)/dashboard/page.tsx`): remove `dashboardCopy.description`, 3 metric cards, hero CTA; compact hero + `data-testid="dashboard-active-count"` chip (only when >0); grid `xl:grid-cols-[minmax(0,1fr)_minmax(0,26rem)]` — left "Mis proyectos" ProjectCards (empty state w/ CTA), right CreateProjectForm. Proof: grep absence + chip presence.
- **U4 — Robust uploads**: `next.config.ts` bodySizeLimit 25mb (+test); DocumentImporter accepts .docx/.doc/.pdf/.txt/.md full MIME; mammoth/pdf-parse in try/catch; parse failure = non-blocking warning.
- **U5 — Optional creation**: CreateProjectForm with 3 optional labeled sections — manuscript (DocumentImporter + blank-start hint), structure reference (existing StructureReferenceSection), brand manual PDF (new BrandManualInput, `name="brandManual"`). `createProjectAction`: best-effort BrandProfile extraction, active + linked; failure never blocks creation.
- **U6 — Preferences & "Datos del documento" modal**: remove EditorPreferencesSidebar from AppShell; device/view selector lives ONLY in Preview and feeds export (`buildExportQueryString`); modal (MODAL_CONTRACT) auto-opens after import analysis, reopenable from workspace + project card; free values (family, pt size step 0.5, margins presets+custom, line-height); structure via extract-structure-profile with confidences; DOCX extraction via JSZip reading word/styles.xml (Normal: rFonts + sz half-points) → "verified in source"; md/txt → defaults "not extracted"; composition scope: project-only (jsonb on project_documents) vs all-projects (user_preferences, optional overwrite checkbox off); brand scope: this-product vs active default profile with explicit per-project choice incl. "no brand"; hierarchy: project > user > system; brand explicit > default > none.
- **U7 — i18n**: new ES+EN keys with parity; parity test green.
- **U8 — Tests**: update dashboard-grid-contract and dashboard-light-contract; new unit tests (styles.xml, modal scopes, hierarchy). Full verification ONCE per U close + once final.
- **U9 — Mandatory visual validation** at each U close: before baseline + after; surfaces /dashboard (expanded+collapsed), /projects/new, workspace step 1, modal open, /preview; matrix 1440×900, 1366×768, 375×667, dark/light; **since P-SHELL-01 (addendum v2.2.1) the matrix also includes 2560×1440**; assertions: no h-overflow, no collapse overlaps, absence of removed elements, chip presence, no avoidable modal scroll; artifacts `test-results/visual/U<n>/before|after-<surface>-<viewport>-<theme>.png`. No green evidence → no commit.
- **P-SHELL-01 (addendum v2.2.1)**: `.talent-shell-grid` max-width becomes fluid `clamp(96rem, 92vw, 128rem)`; named `--breakpoint-3xl: 137.5rem` (2200px) drives a third projects column (`3xl:grid-cols-3`); landing/sign-in stay centered; `dashboard-grid-contract.test.ts` asserts the clamp + 3xl rule. Note: with the 128rem cap the residual side bands at 2560px are 256px/side (10%) — the addendum's ≤5% target would require ~152rem; documented deviation, clamp implemented as specified.
- **U10 — Delivery**: atomic Conventional Commits on `development`, push, PR to development with units, greps, tests, capture paths, Vercel preview URL; note production unchanged until promotion.

## Binding rules
Work only on `development`. Batch verification (lint/test:run/build/tsc, zero NEW tsc errors vs Archive/ baseline) once per U close. i18n ES/EN. Server-side authorization. Code wins — document reality. No scope substitution; if a unit is unviable, deliver the rest and report.

## U6 design (frozen 2026-08-06, binding for implementation)

Forbidden zone (Claude Code, `fix/qa-findings-v1`): `src/lib/brand/*`, `src/lib/preview/*`, `src/lib/compose/*`, export API routes, cover/back-cover studios, `scripts/`, `.gitignore`. Import from them; never edit.

1. **Sidebar cleanup**: remove `EditorPreferencesSidebar` from `AppShell.tsx` and delete `src/components/projects/EditorPreferencesSidebar.tsx` (also clears its 6 pre-existing tsc errors).
2. **Device selector only in Preview**: new `PreviewDeviceSelector` (client) rendered in `/projects/[id]/preview` (inside `ExportLinks` row) writes `setPreferences({device})` via `useEditorPreferences`; `PreviewModal` format buttons also persist `setPreferences({device})`. Export stays fed by `buildExportQueryString`. The editor-canvas device buttons in `AdvancedRichTextEditor` are an editing aid, out of scope (documented, not removed).
3. **Composition model** (new `src/lib/projects/composition.ts`): `CompositionSettings = { fontFamily?, fontSizePt?, lineHeight?, margins? {top,bottom,left,right} }` (pt units, step 0.5; line-height step 0.05), `SYSTEM_COMPOSITION_DEFAULTS` (Georgia 12pt, lh 1.5, normal margins), and pure resolvers:
   - `resolveComposition(projectComposition, userDefaults)` → project > user > system.
   - `resolveBrandProfileId(explicitId, brandChoiceNone, profiles)` → explicit per-project id (incl. explicit "no brand" marker) > active default profile > null.
4. **Persistence (no DB migration)**: per-project composition lives in `project_documents.metadata.composition` (jsonb, via existing `saveDocumentExtras`); user defaults live in `user_preferences.editor_preferences.compositionDefaults` (extends `EditorPreferences`, jsonb upsert via existing actions). Explicit "no brand" marker lives in `metadata.brandChoice: 'none'`; per-project brand uses existing `projects.brandProfileId` + `setProjectBrandProfileAction`. Rationale: jsonb columns already exist; v2.x requires "jsonb in project_documents", which `metadata` satisfies.
5. **DOCX styles extraction** (new `src/lib/projects/docx-styles.ts`): `extractDocxNormalStyle(buffer)` → JSZip reads `word/styles.xml`, takes the `Normal` paragraph style `w:rFonts` (ascii/hAnsi) and `w:sz` (half-points → pt). Returns `{ fontFamily?, fontSizePt? } | null`. Wired into `POST /api/projects/import`: response gains `composition: { settings, source: 'docx-styles' | 'not-extracted' }`; md/txt/pdf or parse failure → system defaults marked `not-extracted`. Never blocks import (try/catch).
6. **Modal** (new `src/components/projects/DocumentDataModal.tsx`, `ac-modal` pattern + Portal, MODAL_CONTRACT: header + close top-right, footer secondary-left/primary-right, no avoidable scroll, `max-width: calc(100vw - 2rem)` mobile):
   - Two modes. `pre-create` (inside `DocumentImporter`, auto-opens when `importState` becomes `ready`): edits composition extracted from the uploaded file; confirm writes hidden form fields (`composition` JSON) so `createProjectAction` persists it into the new project's `metadata.composition`. `project` (workspace): edits and persists via new server actions.
   - Fields, all free values: font family (text input), size pt (`number`, step 0.5, min 6 max 72), line-height (`number`, step 0.05), margins (preset select from `MARGIN_PRESETS` + 4 numeric custom inputs). Source badge: "verificado en fuente" when `source==='docx-styles'`, "no extraído" otherwise.
   - Structure section (project mode only): runs `extractStructureFromDocument(project.document)` client-side and renders hierarchy/pattern with its `confianza` badges (read-only).
   - Composition scope radio: "solo este proyecto" (save to `metadata.composition`) | "todos mis proyectos" (save to `compositionDefaults`; projects without own composition inherit) + optional checkbox "sobrescribir personalizados" (default off; when on, overwrite every project that has its own composition).
   - Brand scope section: select of user's `BrandProfile[]` + "sin marca"; scope radio "este producto" (`setProjectBrandProfileAction`; "sin marca" writes `metadata.brandChoice='none'` + null id) | "todos mis proyectos" (new action sets `brandProfileId` on all user projects; per-project explicit choice still wins).
   - Hierarchy note in UI: composition project > global > system; brand explicit > default > none. Brand contributes families+palette, composition contributes size/margins/line-height.
7. **Server actions** (`src/lib/projects/actions.ts` + reuse): `saveProjectCompositionAction` (projectId, composition JSON | null), `saveUserCompositionDefaultsAction` (defaults, overwriteCustom:boolean), `setBrandForAllProjectsAction` (brandProfileId | null). All with `requireUserId`, revalidate editor/dashboard.
8. **Entry points**: workspace header `ac-workspace-stage__actions` button `data-testid="document-data-open-button"`; `ProjectCardMenu` item linking to `/projects/{id}/editor?documentData=open`; `ProjectWorkspace` reads `searchParams.documentData==='open'` → opens modal (covers the card entry). `createProjectAction` redirect gains `?documentData=open` when a manuscript was imported but the user did NOT confirm the pre-create modal (no `composition` field submitted); if the user already reviewed it pre-create, the redirect stays plain (no double modal).
9. **Export wiring (non-forbidden)**: `buildExportQueryString(preferences, project?)` — when `project.document.metadata.composition` (or inherited user defaults) exists, its pt size/margins override the editor-preference px values in the query. Consumption of composition inside the render/export pipelines (preview/compose/export routes) is a registered DEPENDENCY for the other agent.
10. **i18n**: all new copy under `AppMessages['project']` (`documentData*` keys), ES+EN parity enforced by type + parity test (U7).
